# 佑安服务号：固定入口与首次连接可行性

核对日期：2026-09-25。范围：研究能否内置医院入口，用户在微信正常授权后由 App 保存会话，减少复制粘贴。本轮没有修改产品代码，没有执行医院登录、就诊人切换、锁号或支付。

## 结论

医院名称、服务号指引和公开入口可以预置；个人登录后的身份链接只能保存在本人的设备中，不能作为所有用户共用的固定入口。

**当前 App 已实现成功导入后的加密会话保存和复用。首次导入后，会话仍有效、继续使用同一就诊人时，不需要每次粘贴。** 本轮核对了代码，不代表重新通过真机首次导入、会话有效期或失效恢复验收。

**首次免粘贴连接尚未验证。** 已知医院页面去掉身份参数后没有给出登录跳转；官网二维码提供了公开微信入口，但没有提供医院授权完成后向本 App 回传会话的机制。用户确认只能复制登录后的挂号页链接，因此本轮没有拿到服务号菜单的原始登录入口。不能由此断言医院不存在其他接入方式。

## 实际核对

### 医院页面

以下 GET 使用全新请求，不带身份参数和已有 Cookie，不执行网页脚本。

| URL | 响应 | 能说明什么 |
| --- | --- | --- |
| `https://psc.hkinfo.net/admin/youmanage` | HTTP 400，无 `Location` | 不能把已知登录后首页去掉参数，当作已验证的登录入口 |
| `https://psc.hkinfo.net/regis/initDept` | HTTP 400，无 `Location` | 已知科室页不能直接建立新会话 |
| `https://psc.hkinfo.net/` | HTTP 200，正文“此功能正在维护，稍后发布” | 根路径没有提供本轮可用的登录入口；不代表整个挂号服务不可用 |

此前已取得的科室页、排班页和 `ptcache.js` 中，本轮仅检查路由及脚本引用，未发现登录回调入口；这不是对医院全部代码的扫描，也没有复用旧身份凭据发起请求。

### 官网二维码

[医院官方挂号指南](https://bjyayy.com.cn/Html/News/Articles/44135.html)要求：微信搜索“北京佑安医院服务号”或扫码关注，再进入“就诊服务 → 预约挂号”。

从指南所附[二维码图片](https://www.bjyayy.com.cn/Sites/Uploaded/Image/2023/03/286381560069654746137465915.jpg)离线解析得到：

`http://weixin.qq.com/r/fkjUzNDEj43wrZSv9x1s`

普通 HTTP 客户端访问后，先 302 跳转至同路径 HTTPS，随后返回 HTTP 200 HTML，脚本按语言跳转微信下载页；未执行该脚本，也未在手机微信中实测该二维码。本轮没有从这里获得医院登录入口或授权回传地址。可将它作为公开服务号入口候选，不能承诺它已支持从 Android 一键直达挂号。

### 微信网页授权约束

直接读取了[微信官方网页授权文档](https://developers.weixin.qq.com/doc/service/guide/h5/auth)，确认：

- 该机制针对用户在微信客户端访问服务号网页。
- `redirect_uri` 必须符合服务号配置的网页授权域名。
- 授权码只能使用一次，未使用时 5 分钟过期。
- 换取授权票据需要服务号的 `appid`、服务端 `secret` 和授权码；官方明确要求 secret 和 access_token 仅保存在服务器。

因此，保存固定网址本身不足以让独立 App 自动取得医院会话。不能擅自把医院回调换成本 App 地址，也不能把其他微信应用的登录结果当成医院凭据。这些是平台约束；医院实际菜单的首次授权和可用回传机制仍需单独验证。

## 建议的 v0.1 连接方式

1. 预置北京佑安医院、服务号名称和操作指引；公开入口的手机跳转效果通过验收后再加入按钮。
2. 首次连接仍在微信选择就诊人，主动导入一次登录后链接，完成身份核验后加密保存。
3. 已连接时优先展示当前就诊人和连接状态，正常使用已有会话；失效后引导重新连接。不能承诺一次导入永久有效。
4. 只有验证到医院支持的授权回传，才能把首次导入改成完全免粘贴。微信若能通过系统分享将页面交给本 App，也可作为候选；当前未验证微信是否提供该分享路径，不作为已可用功能。

上述是调研建议，本轮没有实现新的入口、分享接收或连接页调整，也没有更改服务号作为主通路的决定。
