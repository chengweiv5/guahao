## 范围与最新用户观察

用户要求继续北京 114 和京通官方渠道，先解决抓包代理问题，不转向其它平台。采样仅限本人手机中的首页、医院、科室和排班；不操作患者、订单、报告、挂号提交或付款。资料不推送，不发送本轮飞书通知。

用户明确补充：**京通已经登录，114 尚未登录，两边页面看起来相同。** 这是同一现场的用户观察，未读取认证接口、Cookie 或 Token 独立确认。它说明当前两个入口的可见登录状态不同，不支持直接共用会话的设计；还不能证明后台服务完全独立，也不能证明长期不存在单点登录。

设计按入口隔离 Cookie jar、授权状态、失效恢复、就诊人和订单引用。可以研究是否共用目录、排班协议，但不得将京通“已登录”传播成 114“已连接”。114 在未登录状态下可浏览排班是页面级观察，不能据此断言匿名 API、患者管理或提交也可用。之前采样中 Cookie 存在的布尔值不应解释为 114 已登录。

## 两个已经修复的问题

1. **过早拆除代理传输。** 旧运行器收到 TLS 失败就结束代理并删除 `adb reverse`。仍连接旧代理地址的客户端会遇到连接拒绝。真实 USB 探针复现：移除映射后 `ConnectException`；保留代理和映射、切到原样 TLS 透传后 HTTP 202，240 ms。该探针复现的是传输断点，没有复现或证明微信内部缓存机制。
2. **模式监听启动顺序。** mitmproxy 12.2.3 在 Python 3.14 下使用 `asyncio.eager_task_factory`。原脚本先创建任务、后设置 `self.mode`，协程会立即读取不存在的属性并退出，实际一直透传。记录到的异常为 `AttributeError: 'Control' object has no attribute 'mode'`。修复为先初始化状态再创建任务，补充任务异常时退回透传；旧版本失败、修复版本通过的[本地回归脚本](tools/proxy-control-eager-regression.py)已执行。诊断脚本留在明确的 `/tmp/guahao-v02-proxy-repair-20260925` 临时目录；采样运行器的 CA 已删除，不可直接重跑。

新退出顺序：目标客户端 TLS 失败 → 立即停止解密并透传 → 显式设置 `http_proxy=:0` 等待 Android observer → 恢复五个键原始状态并读回 → 保留代理与 USB 映射最多 180 秒，用户确认恢复可提前结束 → 删除本次映射 → 退出代理。启用阶段部分失败也进入恢复。代理仅监听 `127.0.0.1:18888`，没有向局域网开放。

## 为什么再次安装用户 CA 无效

只读复制当前安装的微信公开 APK，检查 Manifest 和资源；未读取应用私有存储，未修改或运行提取代码。

- 微信 8.0.78，versionCode 3180，targetSdk 34。
- Manifest 的 `networkSecurityConfig` 指向 `r/b/b7.xml`，其中信任锚只有 `src="system"` 与 `@raw/globalsign_root_r46`；没有 `src="user"`。
- 内置证书标识通过资源表核对为 GlobalSign Root R46。
- [Android 官方 Network Security Config 文档](https://developer.android.com/privacy-and-security/security-config)说明：系统 CA 默认受信任；targetSdk ≤ 23 才默认包含用户 CA。较新目标版本需显式配置用户 CA 信任。
- 手机时间读回为北京时间 11:58:47，测试 CA 有效期为 11:41:39–19:46:39；该时间在有效期内。
- 京通官方 Android 1.0.6 包 targetSdk 34，网络配置只设置允许明文连接，没有声明用户 CA；本轮未安装或运行该原生 App，不能把其静态配置当作实测结果。

以上足以说明**当前微信声明的网络策略不信任用户 CA，并与两次真实证书拒绝一致**。具体失败连接是否完全走 Android 标准验证实现未独立跟踪；不能将此结论升级为“已经证实证书固定”。代理本身的证书生成、上游验证和故障透传已分别通过测试，不能把这两类问题混写成网络不通。

同一 Android 微信内继续换证书或换代理端口没有新的判别价值。本轮未 root、hook、改包、注入系统 CA、关闭 TLS 校验或提取登录凭据。用户进一步要求以手机微信为验证环境，桌面客户端不作为替代路线；未修改 Mac 信任库或系统代理。12:07 再次只读检查，标准 `webview_devtools_remote` socket 数量为 0；未保存原始 socket 表，未启用隐藏调试。下一项所缺的是手机端可用的正常调试/信任路径或直接可读的官方移动协议证据；现有用户 CA 配置无法继续解密。正式文档是另一种协议证据来源，不是继续研究的唯一前置条件。
