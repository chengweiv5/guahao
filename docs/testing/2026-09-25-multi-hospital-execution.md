# 多医院并行执行验收

2026-09-25。并行框架已实现，真实医院适配器仍只有佑安微信服务号。本轮使用演示医院 A/B 和共享账户结果接口的合成平台验证，没有发起真实医院请求、挂号或支付。

## 实现结果

- 连接目录按医院/来源/账户/就诊人组织，独立保存凭据版本和 Cookie；身份索引使用本机加密密钥 HMAC。旧任务不跟随当前连接切换。
- 不同任务独立启用和执行；同任务 generation/owner 去重。一次实际闹钟会启动全部已到点的等待任务，避免同时放号的闹钟合并造成遗漏。
- 每个平台账户的提交尝试与范围占用同一 SQLite 事务保存。PSC 的账户级异步结果仅供范围所有者核对；未知结果、超时、进程重启和更换凭据都不释放保护。
- 获取范围后重新检查订单基线；限频共享到平台，增加连接不增加预算。PSC 最终网络发送前再次检查停止/截止时间，不透明重试。
- 服务主线程维护 worker 集合，各有 WakeLock；停止一个不停止另一个，最后一个结束才退出前台。静默汇总与每任务结果通知独立，结果 PendingIntent 使用任务 URI，避免 hash 冲突。
- 医院/就诊人选择、任务卡、详情和通知展示各自医院。测试版增加演示 A/B；release 拒绝 demo 前缀和 demo 标记。
- 同身份新连接可显式更新已停止且未提交任务；保留原时刻并回到草稿。未决/订单任务使用新连接只读核对，原尝试和身份绑定保留，不触发锁号或医保初始化。

短时锁屏测试在登记闹钟前调用系统熄屏并断言屏幕关闭，两条任务和通知成功。本轮未连续采集屏幕状态；不能据此声明全过程屏幕一直关闭。30 分钟以上锁屏、深度 Doze、双提交过程中系统重启/断网与真实多医院流量仍需单独验收。既有铃声/双振动用户确认属于之前的版本，本轮回归了系统通知属性与生命周期，没有新的主观听感确认。

## 数据迁移与回退

schema v1 → v2 由 SQLiteOpenHelper 事务完成，保留加密任务负载并补归属，移除全局 owner 索引，增加 submission_scopes。升级事务中 `v1_migration_backup` 保存升级前的加密原行；任何迁移异常使事务整体回滚。身份无法识别的历史未决持有 PSC 平台通配范围，连接入口仍可用。

本机源码与手机加密数据库/APK 备份：`/tmp/guahao-parallel-before/`。备份不进仓库，解密仍依赖原安装的 Android Keystore。升级产生新业务后禁止恢复旧数据库或安装不理解 v2 的旧 APK；回退必须保留 v2 存储兼容，撤回功能代码，或在确认没有新增业务时由用户决定恢复。不得 clear data 或卸载应用。

## 实现边界

第二家真实医院尚未确定；本轮没有声明多家真实医院挂号已实测。每个新平台必须提供经验证的身份、订单关联范围和请求限频规则。当前 PSC 同人导入保留 `id=oldId`，不执行跨人切换；跨患者服务端选择副作用尚未验证，接入会改变服务端选择的新适配器时必须将该初始化步骤与同账户提交协调。

连接目录回填当前会话及历史任务引用的版本；未被任务引用且不是当前的旧版本文件仍保留，但不扫描恢复为目录条目。任务详情读取自身版本的状态，同一逻辑连接目录显示最近导入版本。

完整结构化结果、APK 哈希和原始测试回执：[parallel-verification.json](evidence/v0.1/parallel-verification.json)。当前 debug 已原位安装到手机且哈希回读一致；release 仍为本地未签名产物，未发布。
