# 佑安服务号链接导入失败排查

用户从就诊首页 `/admin/youmanage` 复制链接，连接时看到“操作未完成，请检查输入、医院连接或网络后重试”。该路径原本就在允许列表内；仅凭通用提示不能认定首页链接不受支持，也不能认定是网络故障。

## 已复现和修复

- 模拟器通过实际“连接并核验就诊人”按钮提交无效输入，稳定复现用户看到的通用提示。解析器抛出的 `IllegalArgumentException` 原先落入 UI 的兜底分支。
- 完整合法链接只要前后带空格或换行也被拒绝。现在仅去除首尾空白，仍拒绝链接内部空白、非 HTTPS、非白名单主机/路径、重复参数、控制字符等；凭据只解码一次，保留加号。
- 链接缺少就诊人参数、页面不支持分别显示固定提示。导入各环节显示“打开医院页面 / 核验就诊人 / 获取就诊会话 / 校验挂号功能 / 保存医院连接”。不拼接原始异常、链接或医院响应正文。
- 对异常就诊人列表、异常会话结构和身份不一致给出可读错误；核验失败不改当前连接指针。原任务继续使用原有连接。

## 验证

修复前：链接空白单元测试失败；无效输入和异常响应的仓储测试失败；真实 UI 回归断言捕获通用错误（5.602 秒）。

修复后：核心测试 31/31，Android JVM 测试 20/20；debug 构建、测试 APK 构建及 lint 通过（0 错误，9 项既有 UseKtx 提示）。模拟器 UI / 连接状态回归 5/5，18.125 秒。测试数据全部虚构，未调用真实医院。

Mate 60 Pro 无运行中的 BookingService 时已保留数据升级；安装 APK 回读 SHA-256 与本地产物一致：`3547c31b8d021d4d751fd8ed61779b112edf3142a8a9f154b7438bf3151e4557`。

当时尚待用户在手机中重试确认。上述脱敏测试不能替代真实医院连接验收；后续反馈见下。未读取微信私有数据、剪贴板或真实身份链接，未锁号或付款。

### 后续反馈：首页链接缺少登录凭据

用户重试后反馈“缺少就诊人身份信息”，并报告首页链接参数有 `ptno` 和 `userId`。按这个参数结构以虚构值重放，仓储回归复现原提示，且没有发出网络请求或修改已保存连接。当前导入流程还需要 `userIdKey` 登录凭据；两个编号不能替代它。

已将缺少 `userIdKey` 的提示改为“链接缺少医院登录凭据，请在微信进入「预约挂号」后重新复制完整链接”，缺少就诊人编号仍显示原来的就诊人提示。

用户按指引从微信“预约挂号”的科室列表页重新复制链接，在手机现有诊断修复版中导入，明确反馈“科室列表页链接导入成功”。这项真实连接结果来自用户反馈；没有读取其凭据或发起额外挂号/付款，也未验证会话的自然有效期。当前问题已通过正确页面的链接解决；后续复用已保存连接，失效后同样从科室页重新接入。

该补充改动核心测试 31/31、Android JVM 测试 21/21；debug 构建和 lint 通过。页面回归见 [缺凭据提示验证](evidence/v0.1/session-import-missing-credential-ui.txt)。细化提示的补充版本暂未安装到手机，手机成功连接使用的是前述 `3547c31b…` 版本。

共享模拟器在另一个对话的测试中升级为数据库版本 2，本次最初覆盖安装了数据库版本 1 的 APK，导致测试启动时出现降级异常，测试未执行、数据未删除。已恢复另一个工作区构建的 App / 测试 APK，App 回读 SHA-256 为 `afa732719aa692c27ada5b1a0699a2a1f06d594ae185772b4b8d31b4d824a795`；随后改用临时 `cn.guahao.importcheck` 包进行隔离验证。未修改生产数据库以迁就测试。

证据：[修复前 UI](evidence/v0.1/session-import-error-before.txt)、[修复后模拟器](evidence/v0.1/session-import-error-emulator.txt)、[汇总](evidence/v0.1/session-import-error-verification.json)。
