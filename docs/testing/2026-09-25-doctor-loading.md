# 佑安医生加载失败修复

用户在真机选择“肝病中心一科”后收到“医生加载失败，请刷新科室或重新连接”。使用手机内已有会话重放同一查询，复现 `PscPageParser.schedule` 第 58 行的 `IllegalArgumentException`。医院返回 16 天排班，其中 8 天的 `registryList` 为 JSON `null`；客户端直接按数组读取，导致其他有排班日期的医生也无法显示。

修复将明确的 `registryList: null` 当作当天无排班，继续解析其他日期；空数组同样有效。字段缺失、对象或数字仍抛出可读的排班结构错误，不用空列表掩盖异常。各时段余号、候补标识、费用和提交条件保持原有规则。

## 验证

- 修复前：真机只读查询 1/1 失败，2.298 秒；脱敏响应缩减成混合空日期/有排班日期的回归样例，单元测试同样失败。
- 修复后：同机同科室只读查询 1/1 通过，1.331 秒，返回 14 位医生、113 个时段。此数量是当时结果，不是固定库存。
- 实际表单：选择真实挂号、科室和医生列表，1/1 通过，9.518 秒；没有加载失败提示，医生选项非空，选择前后任务记录相等。第一次测试因未等待连接异步加载，在科室弹窗处超时；补等待连接和按钮启用后通过，未因此修改产品逻辑。
- 核心 37/37、debug/release 单元测试各 23/23 通过；debug/release APK 构建通过；两种 lint 均为 0 错误、13 个已有 `UseKtx` 建议。
- 真机专用 `LiveDoctorQueryTest` 默认跳过，必须明确传入 `liveHospitalProbe=true` 和科室名才查询医院。最终默认开关验证为 2 项跳过；临时排班抓取逻辑已移除。直接查询使用内存覆盖层，凭据不离开手机；UI 测试会触发正常前台连接检查，但不保存或启用任务。

验证证据：[结构化结果](evidence/v0.1/doctor-loading-verification.json)、[真机修复前](evidence/v0.1/doctor-loading-device-before.txt)、[真机修复后](evidence/v0.1/doctor-loading-device-after.txt)、[实际界面](evidence/v0.1/doctor-loading-ui-after.txt)。
