# 京通任务与订单集成验证

日期：2026-09-26。基线：`0ba15c9a63c88d6aa35d64570995d1c46ae1ca5a`。本轮优先实现京通，114 授权不作为京通前置条件。

**本地实现与合成验证完成，真实预约链路尚未验收。** `JingtongCapabilities.automaticBookingVerified` 保持 `false`，网关、浏览器服务和 UI 禁止启用自动提交。允许保存京通草稿；不能将这批代码称为已经支持多医院自动挂号。

## 已实现

- 京通就诊连接按不可变版本保存，旧任务保留原患者和卡；任务使用本机引用，账户级 HMAC 提交范围跨医院共享。
- 医院、科室、日历、医生排班接入四步任务。产品键与时段键分别保留；未知价格、余量、时间、候补及生成时段不能成为候选。
- 草稿保存、重开、患者重验、原渠道订单入口、到院取号提示接入 UI。京通不显示佑安的医保初始化或服务号导入指引。
- 固定订单列表和详情通过私有 Binder 提供，前后核验账户一致；严格校验患者、医院、日期、分页总数、重复与旧版订单。无法完整识别的列表不当作空基线。
- 提交实现只允许固定 `product/confirmV2`、`auth/order/save` 参数。提交 `cardType` 取所选卡的 `medicareType`；未实现官方脚本中的自动重试。
- 发送前持久化标记，成功时保存订单号。任务、批次和候选共同生成摘要；丢失响应或存储失败不再次发送。浏览器向主进程核对停止状态、批次和条件，随后检查原截止时间。
- 按任务和候选读取本地提交凭据，浏览器重建时无需初始化网站；订单查询仍需正常登录。新出现且条件相同的订单必须与持久化订单号一致，才能归属于本任务。
- 预约成功待取号、待付款、完成、取消及未知状态分开处理；京通不会调用佑安医保接口。

1. **最新现场状态：手机已连接，见下方真机增量。** 两院查询与固定订单操作已验证；后台对照测试等待用户手动解锁及临时包后台权限。
2. **非空订单与详情。** 之前最近 30 天列表为空；最近一年查询仍待用户授权。当前详情字段、时间格式、状态及支付逻辑来自官方静态脚本与合成测试，需真实非空订单核验；医生编码和订单归属字段的存在性也不能凭测试认定。
3. **确认与提交。** `confirmV2` 的实际响应及是否预占、实名/国籍/虚拟号码/人脸规则、取退号提示确认及可选 `partnerUid` 仍需核验。规则未满足时暂停，不能简单翻转能力开关。没有实际就医条件与明确授权，不为测试制造真实预约。
4. **同单恢复边界。** 已保存成功回包可经本地凭据找回；若服务端建单但本机从未收到订单号，仍是未决结果，不能根据唯一新订单猜测关联或再次下单。
5. **运行和付款交接。** 锁屏、长后台、进程死亡恢复、官方付款跳转尚未验证。入口只打开同渠道官方页，由用户定位订单；不声称已支持支付 SDK 或支付深链接。浏览器重建后的查询要求用户正常打开连接页。
