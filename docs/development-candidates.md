# 后续开发计划候选

记录日期：2026-09-25。

以下记录用户提出的后续方向。2026-09-25 用户已指定“北京通用挂号平台”为 v0.2，并要求本任务先完成设计；开发时间尚未确定。其余方向仍为候选，未排期。

| 候选方向 | 内容 | 状态 |
| --- | --- | --- |
| 扩展医院 | 增加其他医院，例如北京宣武医院。 | 候选，未排期 |
| 北京通用挂号平台 | 调研并支持北京通用的挂号平台接口，以覆盖更多医院的挂号需求。见 [v0.2 设计](design/v0.2/2026-09-25-beijing-platform-design.md)与[平台调研](research/2026-09-25-beijing-platform-landscape.md)。 | v0.2 设计稿待评审，开发未排期 |
| 接口来源可选 | 支持用户选择接口来源，例如微信服务号、互联网医院、114 挂号平台。 | 候选，未排期 |
| 扩展其他城市 | 调研并支持其他城市的挂号平台接口。 | 候选，未排期 |

当前 v0.1 的需求与范围见 [v0.1 需求与实现方向](design/2026-09-24-v0.1-requirements-and-approach.md)。

v0.2 设计包含“每个任务固定一个已验证渠道”的必要选择流程；不代表将通用接口来源选择、宣武医院独立渠道或其他城市候选全部纳入本版。v0.1 在其它任务开发，本任务不调整其实现。
