# 按日期查询排班 · 界面方案

状态：用户确认后已完成 Android 实现，2026-09-25 已覆盖安装到 Mate 60 Pro 并通过日期状态、预选医生及确认页验收。[实现验证记录](../../testing/2026-09-25-daily-schedule.md)。

## 流程与展示

按用户确认的顺序：选择科室 → 选择就诊日期 → 查询当日排班 → 选择医生。

推荐在“新建挂号任务”的第一步完成。保留医院、就诊人和“是否专程来京就医”；科室为可搜索选择入口，日期使用快捷日期与完整日期选择器。点击“查询当日排班”，结果直接出现在日期下方，医生不再另开一个混合多天排班的弹窗。

当天排班已发布时，医生卡片显示姓名、职称（有则显示）、当天出诊时段、费用和当前号源状态；整张卡片可单选，选中后显示勾选和底部摘要。确认条件后进入原有执行设置。

当天医生尚未发布时，显示明确的“预选目标医生”按钮。点击后从医院已确认的本科室医生名单中单选，卡片只展示医生身份，并标记“目标日排班待确认”。选中后可继续设置放号时间；可接受时段仅表示用户偏好，不代表该医生当日有出诊。底部保留目标日期、医生及待确认状态。

## 状态

### 强制区分：未放号与当日无号

这两种状态必须使用独立的判断、标题和后续提示，不能合并为“暂无号源”。颜色只能辅助区分，文字必须明确；选择或预选医生后，仍保留医院返回的日期号源状态。

| 日期号源状态 | 判定依据与含义 | 界面及任务提示 |
| --- | --- | --- |
| 未放号（界面标题“尚未放号”） | 医院明确返回目标日期尚未开放挂号 | “尚未放号”；可预选医生、设置放号时间，到计划时间再查询实际号源 |
| 当日无号 | 医院明确返回该日期当前没有可挂号源 | “当日无号”；可换日期，也可按已设置的执行窗口等待可挂号源出现，不显示“等待首次放号” |
| 暂未查到当天排班 | 日期缺失、未知状态或信息不足 | 保留未知状态，可重试、核对或预选医生；不能推断为未放号或当日无号 |
| 查询失败 | 网络、会话或响应解析失败 | 独立显示错误及恢复入口，不覆盖成未放号或当日无号 |

“当日无号”只说明当前没有号，不能自行解释为已抢完、无医生出诊或医院停诊。“尚未放号”也不等于医生排班未发布：医院可能提前发布排班但暂不开放号源。日期号源状态与医生的目标日排班确认状态分别保存、展示；例如“尚未放号 · 排班已发布”与“当日无号 · 目标日排班待确认”都可能成立。

判定以当前医院的已核实状态语义为准。佑安服务号已观察到 `syqty=0` 对应无号，`-2/-3` 进入待放号逻辑；这是医院适配规则，不是跨医院通用编码。`registryList:null`、空列表、医生筛选后无结果，以及用户设置的放号时间，都不能单独作为上述两种状态的判据。单个医生无号显示“该医生当前无号”，不扩展成整个日期无号；仅用户筛选条件无匹配时显示“暂无符合条件的号源”。

验收要求：在同一科室下，即使两次响应都没有医生列表，也必须分别显示未放号和当日无号；预选医生不改变日期号源状态。到达用户配置的放号时间后，按医院的新响应更新状态，不因手机时钟到点就把未放号改成当日无号。确认页与任务详情继续保留这一区分。

### 交互状态

| 状态 | 展示 | 后续操作 |
| --- | --- | --- |
| 日期或科室改变 | 清空旧排班和医生，提示重新查询 | 查询当日排班 |
| 查询中 | 查询按钮显示进度，旧医生不可选 | 等待本次结果；若条件改变则忽略旧请求 |
| 有当天排班 | 只列当天医生，分别标注有号或无号 | 单选医生，设置可接受时段 |
| 当日无号且未返回医生 | 显示日期、科室和醒目的“当日无号” | 更换日期，或从已确认的科室名单预选医生；未选择前下一步禁用 |
| 尚未放号且未返回医生 | 显示“尚未放号”及“预选目标医生”入口 | 预选医生后，带“目标日排班待确认”状态继续 |
| 日期不在医院返回范围 | “暂未查到当天排班” | 可预选目标医生、重试或去服务号核对；不得误标为无号或尚未放号 |
| 查询失败 | 展示可理解的网络或会话错误 | 重试或重新连接；不得误标为无号 |
| 科室医生名单不可用 | 显示“暂无法预选医生”及重试入口 | 不以自由输入姓名代替已验证医生身份；恢复名单后再选 |

医院已明确返回的当天医生即使目前无号，也可以作为该日任务条件。科室名单可以来自同一医院、同一科室的可靠医生目录或医院已返回的其他日期排班，但只能用于确认医生身份，不能把其他日期的费用、时段或余号视为目标日信息。不能凭医生同名合并身份，也不能从公开网站的 ID 推断服务号医生编码。

放号时重新查询真实排班，严格匹配医院、科室、目标日期、指定医生及可接受时段，再执行原有挂号流程。未找到匹配项时在配置的执行窗口内等待；截止后说明“未查到符合条件的号源”。不自动替换医生、日期或医院，不把预选成功显示为锁号成功。后续确认页、任务详情持续显示待确认标记，直到目标日排班已核实。

放号时间仅在医院确实返回时展示，否则由用户设置，不由样例日期推算。

## 提前排班的证据边界

已观察的服务号样本中，2026-10-10 为待放号状态且 `registryList:null`，未提供当天医生；2026-10-02 为无号且同样未提供医生。这说明这些响应缺少目标日排班，不能推论医院所有接口都查不到提前排班。医院[公开周排班](https://www.bjyayy.com.cn/Html/Hospitals/Schedulings/OPIndex0_0.html)仅表示常规星期安排，并注明以当日挂号为准，不能作为指定日期、尤其节假日的出诊确认。

本稿为完整内容展开图；实际 Android 页面内容滚动，底部摘要与下一步使用系统安全区。演示数据、显示日期和病例科室不代表当前医院实时库存。

交互预览默认展示尚未放号日期。验收覆盖预选入口、医生单选、待确认标记、启用下一步，换日期或科室清空选择，以及有当天排班和当日无号的区别。具体检查结果见校验记录。所有预览交互均使用合成数据，不调用医院接口。
