## 设计方向

暖白背景、深青绿主要操作、琥珀色付款及异常提醒。首页集中呈现下一次放号，不堆叠医院资讯。大号时间让用户快速区分“何时开始”和“付款何时截止”。

基础画布宽度 412；内容高度随内容展开，便于完整评审。实际 Android 页面使用可滚动内容区，顶部与底部操作区遵循系统安全区；关键操作固定在可触达位置。画稿不是设备逐像素截图。

- 主色 #176B5B，背景 #F5F6F2，正文 #17342F，次要文字 #60726D。
- 卡片圆角 20；按钮圆角 14、高 52。
- 正文 14–16，页面标题 26，关键时间 40–58；辅助信息最低 12。
- 可交互行、返回和通知入口按至少 48 dp 触控区域实现。
- 状态同时使用文字、图标、颜色；锁屏默认隐藏就诊详情。通知标题使用“锁号成功，请在 08:16 前付款”（时间为示例）。

## 用语约定

App 内统一使用“挂号任务”“自动挂号”“挂号记录”。锁定号源但尚未付款时显示“锁号成功，待付款”；支付确认后显示“挂号已完成”。医院官方菜单引用“就诊服务 → 预约挂号”保持原文。

## 交互约定

主流程：首次使用 → 连接医院 → 确认就诊人 → 就诊条件 → 执行设置 → 确认启用 → 等待放号 → 执行中 → 待付款 → 微信官方付款 → 返回刷新 → 挂号完成。

- 运行时长默认 30 分钟，可以修改，计时起点是设定的放号时刻。超过时长后不再查号或新提交；已产生的订单继续独立跟踪支付状态。
- 运行时长不能用作付款倒计时。付款页的期限、费用、挂号时段读取医院订单；未知期限时显示“以医院订单为准”，不虚构分钟数。
- 任务只使用用户选择的就诊人、科室、医生、日期和时段。没有号源时不自动替换条件。
- 提交前重新核验条件和费用上限。发现有效订单后停止查号，防止生成多个挂号。
- 已提交、待付款、已付款是不同状态；不使用“已付款”表示仅创建了订单。
- 请求结果不明确时进入核对状态；没有排除已有订单前，不开放重复提交。
- 用户选择医保后，医保不可用时显示待处理并通知。不得静默改为普通支付。
- 用户在微信完成医保授权和支付。App 刷新医院结果后才显示“挂号已完成”。
- 启用前检查登录、就诊身份、精确定时、后台运行与通知。缺失项列出恢复入口。
- 配置中的默认值修改只影响新建任务；编辑已启用任务需重新检查并重新调度。
- 运行中停止仅停止本次任务，不等同于取消已有医院挂号。取消/退款进入医院官方订单。
- 科室和医生选择使用可搜索单选列表；就诊日期、放号日期和时间使用系统选择器。无可选数据时展示原因与刷新入口。
- 自定义时长支持正整数分钟；合理上限、输入校验和放号时间是否过期在实现前定稿，不默认承诺无限运行。

## 已知实施依赖

服务号普通与医保支付的验证成果沿用现有研究。此次未调用医院接口，也未进行真实挂号或付款。

以下是产品预期，不能因设计稿出现按钮而当作已实现：
1. 手机上的服务号会话连接/导入。首次连接页描述用户目标，最终交接方式仍需 Android 验证；不能假设微信登录态自动共享给第三方 App。
2. 微信服务号/医院订单跳转、医保授权与支付返回。如果不能直达，需提供明确的官方服务号订单入口，不把凭证或敏感链接暴露在页面。
3. 鸿蒙 4.2 的精确定时、锁屏后台执行与回收恢复。华为设置引导应根据实机系统页面调整；权限通过并不意味着后台绝对可靠。
4. 通知样式遵循系统模板；锁屏图仅表达内容层级。正文避免展示患者、科室与医生。
5. 数据加载、失败/空列表、任务冲突与网络恢复需在 Android 阶段补齐，复用本设计的反馈模式。
