## 设计目标与取舍

保留“任务 / 记录 / 设置”三个导航入口。用户从医院进入，通过渠道核对身份，再设置就诊条件。平台管理放在设置内，同时能从新建流程进入。

| 方向 | 优点 | 取舍 |
| --- | --- | --- |
| 沿用青绿，重排信息层级（采用） | 保留识别感，改动直接服务多医院任务 | 新建流程增加医院与渠道一步 |
| 全面改成蓝白医疗风 | 外观变化明显 | 无法单靠换色解决流程和状态问题，迁移成本更高 |
| 大字简化版 | 对长辈更易读 | 会增加页面长度；本版先保证正文与触控尺寸，专门大字模式后续另评 |

用户已选择第一项。界面避免营销式“抢号成功率”或未经验证的医院覆盖数字，重点让人知道当前任务、下一步和受阻原因。

## 现有 UI 的具体优化

| 当前基线问题 | 新设计 |
| --- | --- |
| 首页同时重复产品说明、日期、大时间、排班摘要、运行时长和价格 | 每卡保留状态、医院、院区/渠道、医生、就诊日期；费用与执行细节下沉到详情 |
| 所有任务的时间都放大，多个任务难扫读 | 列表用紧凑的放号时间；进入任务详情后才展示单个主时间 |
| 连接摘要与运行准备混在首页长卡片中 | 首页仅保留简短准备提示；设置分别管理“平台连接”和“运行准备” |
| 新建表单包含较多串行依赖字段 | 四阶段流程；每阶段只处理当前决策，已选医院和渠道持续可见 |
| 当前连接与旧任务连接的解释很长 | 平台独立状态 + 任务具体恢复操作；异常说明按需出现 |
| 结果详情同时出现多种主要操作 | 待付款以“到原渠道查看本单”为主要操作，刷新为次级操作 |
| 长页面按钮容易离开屏幕 | 主操作与底部导航固定，内容区域滚动；完整图稿则展开内容 |
| 图形字符代替图标，文字密度不一致 | 统一线性图标、字号、间距与状态标签；不用颜色单独传达状态 |

## 页面与交互

### 任务首页

顶部显示等待任务与草稿概况，有待付款订单时展示一条明确入口。任务卡按医院区分，每张卡包含医院全名、院区和原渠道。等待任务显示计划时间，未连接草稿显示“待连接 / 完善草稿”。任务筛选可切换医院。

多医院任务独立执行。一个医院出现订单，不默认停止或取消其他任务；本次 UI 不新增 v0.3 的竞速策略和重复强提醒。只有适配器判定的相同账户冲突范围受限时，受影响任务显示“暂缓提交”，解释原因并进入原尝试核对。

### 新建任务：四阶段

1. **医院与渠道**：搜索名称、区县筛选，核对院区。逐渠道展示能力和连接状态。京通已连接不使 114 自动显示已连接。目录加载失败和搜索无结果分别展示。
2. **就诊条件**：先核对该渠道的就诊人，再选科室、就诊日期、医生与时段。实际就诊人不默认为登录账号。特定平台要求的“专程来京就医”等字段按平台出现。
3. **执行设置**：医院已返回且可确定的放号时间自动带入，明确北京时间和来源。最长运行时长默认 30 分钟，可选或自定义；费用上限和支付偏好单独设置。
4. **确认任务**：完整列出医院、院区、渠道、就诊人、科室、医生、就诊日期、时间、费用和支付偏好。展示可修复的准备项，核对后才启用。

切换医院、院区、渠道时，清空依赖的就诊人、科室、排班、医生、时段与规则确认；重新获取后继续。切换就诊人、科室或日期清空医生/时段选择并要求重新查询。回到上一步保留仍有效的输入；不得静默复用另一渠道的 ID 或会话。

### 日期与排班

日期条每项同时显示日期和可判定状态。未来日期允许选择，通过“更多日期”打开系统日期选择器。查询状态与医生选择分开处理：

| 查询状态 | 展示与允许行为 |
| --- | --- |
| 未查询 | 请求查询当前日期，不展示过期医生选择 |
| 有号 | 显示医生、费用和实际时段；医生与时段组合选择 |
| 当日无号 | 明示“这一天暂时无号”；可换日期或预选医生等待后续号源 |
| 尚未放号 | 明示“这一天尚未放号”；允许从已知科室医生名单预选 |
| 读取失败/未知 | 明示状态未知和重试入口；不能转为无号或未放号 |

预选仅保存意向，保留原日期状态并显示“目标日排班待确认”。已预选医生可以继续设置，但执行前必须重新核实日期、医生、时段、费用和平台能力。不得以预选替代已公布排班，或自动更换医生。

空医生名单、筛选无匹配和指定医生无号不推断全日无号。加载时保持已选上下文，禁用依赖操作并显示进度；新请求返回前不能提交旧数据。

### 平台连接

目标流程是“官方验证 → 回来校验 → 核对就诊人”。每个平台分别展示未连接、校验中、已连接、连接失效。缺少就诊人时，提示到该渠道添加并回来刷新，不允许进入下一步。

**连接回传仍是技术依赖。** 114 菜单不具备复制链接功能，产品不能要求复制链接。不能要求安装 CA 或执行调试命令，也不假设微信会话能自动分享给本 App。原型“校验通过”是合成结果；正式入口必须通过真实认证验收后才开放。

更新连接不会使旧任务自动继续提交。无未决提交的任务可核对身份后重新启用；有未决提交的任务仅用相同身份的新连接核对原尝试。移除本机连接前检查其任务/订单依赖，保留未决核对必要资料。移除连接不等于取消预约。

### 任务与结果

“等待放号 → 正在查号 → 提交/核对 → 有效订单/未挂到/需处理”按真实业务状态展示。结果未知时主要操作为核对本次结果，不提供直接重复提交。停止操作仅停止当前任务的后续尝试。

订单保留原医院、院区、就诊人和渠道。待付款显示医院返回的真实截止时间；缺失时显示“付款截止时间未返回，请立即到官方订单核对”，不生成倒计时。用户从外部页面返回、点击刷新或表示已支付，都不能直接改成已付款；只有医院结果确认后展示“挂号已完成”。医保不可用时提醒处理，不静默转自费。

官方订单不能直达时展示可操作的人工路径。取号、报到、取消与退款进入原渠道规则，未知规则不补造。锁屏文案不展示就诊人、科室或医生等详情。

## 视觉与可达性

| 项目 | 规格 |

| 主色 / 背景 | 青绿 `#176B5B` / 浅暖灰 `#F4F6F2` |
| 正文 / 次要文字 | `#173B33` / `#5C6F67` |
| 提示 / 错误 | 琥珀 `#835419` / 红 `#A23E36`，同时有文字或图标 |
| 标题 / 正文 / 辅助 | 26 / 16 / 13–14；数值重点 40 |
| 布局 | 20 水平边距，24 区块间距，12–16 相关信息间距 |
| 点击区 | 主要按钮高 52，常规交互最小高 48；图标按钮 48×48 |
| 圆角 | 字段 10、按钮 12、任务卡 16；底部导航集中承载顶级入口 |

主要操作不依赖悬浮或长按。单选态同时有描边/勾选，输入有可访问名称，键盘焦点清楚；开启减少动态效果时停用过渡。Android 阶段仍需在 Mate 60 Pro、系统字体放大、TalkBack、键盘弹出、横竖屏/安全区下实测。

## 当前能力与设计目标

交互原型默认是“目标体验 · 合成数据”，清楚标在评审面板。可切换“当前能力边界”，此时 114/京通自动任务入口禁用，不把官方网页可查号或官方已登录当作独立客户端已接入。两院查询观察、独立鉴权/请求构造与实际提交是不同验收项，见 [v0.2 平台设计](../v0.2/2026-09-25-beijing-platform-design.md)。

原型不访问医院、不保存真实身份、不调起真实订单、不自动付款。所有示例人物、费用、医院放号时间和就诊安排都是合成数据；医院名称使用候选范围，不代表医院承诺或已支持清单。

## 验证与后续开发

已实际完成本机浏览器的 26 项交互/边界检查，以及 24 页在 360 和 412 宽度下的布局检查。检查包含渠道/日期/科室变更失效处理、未放号与无号的区别、预选继续、费用校验、准备项阻塞、停止确认、历史订单原渠道、付款不误报成功、未知期限和目录错误恢复。原型无外部网络请求和 JavaScript 错误。

全部 24 页完成中文 OCR（599 行）和逐页总览检查；固定主操作区域和窄屏文字另外检查。验证范围是设计与本地原型，不代表 Android、无障碍读屏、平台认证或真机后台执行通过。

开发接力收到后，将这些页面映射到既有领域状态，先替换布局再接平台能力；不改变已验证的提交防重、账户隔离和订单核对语义。实现与推送完成前不通知 v0.3 启动。
