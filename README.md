# 医院挂号

面向华为 Mate 60 Pro / 鸿蒙 4.2.0 的 Android 挂号应用，以北京佑安医院为首个接入案例。

用户提前设置就诊人、科室、医生、就诊日期和放号时间。App 在放号窗口内按条件尝试挂号，锁号成功后停止查号并通知用户付款。任务最长运行时长默认 30 分钟，可配置；付款时限以医院订单为准。

## 当前状态

项目已完成服务号单笔挂号与手机付款流程验证，以及 v0.1 的 18 页 UI 设计初稿；当前处于设计与开发计划评审阶段，尚未创建 Android 工程，没有可安装的 APK。服务号为主通路，互联网医院保留为独立研究渠道。

- 微信服务号：已有会话下的就诊人、科室、排班和分时余号查询，以及一次锁号、手机订单可见和同一订单“已预约”状态回查已有验证记录。v0.1 当前采用该渠道，付款由用户在微信服务号完成。
- 互联网医院 App / 网页：独立短信登录、会话检查、就诊人和号源查询已验证，保留为独立研究渠道。两个渠道的会话、就诊人列表和订单可见性不能视为互通。
- 医保支付：单笔初始化后同单状态 `1 → 7 → 6`，医保状态查询返回“支付成功”，用户确认手机结果页“医保缴费”流程已跑通。
- 待验证：服务号首次认证与失效恢复、Android 集成与异常提交恢复，以及目标手机的定时唤醒、锁屏网络和后台运行。

支付偏好为优先医保移动支付。锁号后初始化医保，官方结果列表按状态 7 提供“医保缴费”，手机重新获取授权参数并完成付款；此前遗漏该分支的判断已修正。医保不可用时提示用户处理，不自动改为全额支付。付款期限逐单读取，不因初始化医保而延长。

这些结论来自单医院的有限验证，不代表接口长期可用，也不构成其他真实挂号的授权。具体实现方案仍待评审。

## UI 设计

- [Pencil 可编辑源稿](design/guahao-v0.1.pen)
- [逐页预览](design/ui-v0.1/index.html) · [18 页 PDF](design/ui-v0.1/export.pdf)
- [设计说明与交互约定](docs/design/ui/2026-09-25-v0.1-ui-design.md)

设计使用眼科示例，人物、医生、费用和时间均为虚构数据。App 内统一使用“挂号任务”“自动挂号”“挂号记录”；锁定号源后显示“锁号成功，待付款”，支付确认后显示“挂号已完成”。引用医院官方菜单时保留原文“预约挂号”。

下载仓库后可直接用浏览器打开预览文件，也可在仓库根目录运行 `python3 -m http.server 57123 --bind 127.0.0.1 --directory design/ui-v0.1`，访问 `http://127.0.0.1:57123/`。预览只用于设计评审，不连接医院。
